# 6 步学习法

每个 Step 都按同一套闭环执行。顺序不能跳，但可以按已有基础加速。

| 步骤 | 动作 | 最低产出 |
|---|---|---|
| 看 | 用视频建立直觉，记录 3 个疑问 | 问题清单 |
| 读 | 用官方文档、书和论文回答问题 | 带来源的答案 |
| 跑 | 从空环境复现例程，记录版本和报错 | 可复现步骤、问题表 |
| 改 | 至少改一个模型、参数、任务或接口 | 改动前后对比 |
| 创 | 提出一个可验证的小假设并做实验 | 数据表、图、结论 |
| 写 | 写 README、论文笔记、周报或博客 | 可分享的链接或文档 |

## 每个任务的记录方式

开始前只写三行：

```markdown
目标：
验收：
证据：
```

完成后补齐四类信息：

```markdown
结果：
失败与原因：
仍然不懂：
下一步最小实验：
```

## 完成的定义

下面四项缺一不可：

- 能独立解释核心原理。
- 能从干净环境按自己的步骤复现。
- 有图、表、日志、代码或视频作为证据。
- 能回答“为什么这样做”和“还有什么方案”。

## 卡住时的规则

某一步超过计划时间 50% 后：

1. 记录当前报错、环境、已经尝试的方案。
2. 缩小问题到一个最小命令或最小代码。
3. 先跳过非主线问题，继续完成本周验收。
4. 在周报“卡点”中写清需要谁提供什么信息。

连续三天都无法突破时，再向导师、师兄、课程社区或上游仓库 issue 提问。
